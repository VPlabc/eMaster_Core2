Relay & AUX Relay

              

                
One command with two address types: a user relay
                  is a door/lock output, an AUX relay an auxiliary output.
                  ON latches and stays latched — there is no timer behind it, so a door
                  relay left ON is a door left unlocked until something turns it off. Use PULSE unless you are
                  holding a relay to put a meter on it.


                

                  These fire on the live controller. A lock relay pulsed here opens a real door, and the
                  SmartLocker state machine will not know why.

                AUX Inputs
                --
              

              

                
Auxiliary inputs are event-driven: the SDK has no
                  read-input call at all. An input announces itself as an RTLog edge (220 open, 221 shorted) and
                  is silent otherwise, so one nobody has triggered since start-up has no state to show —
                  it is listed as unknown rather than invented as LOW. Trigger it once and it appears.
                  RTLog must be running for edges to arrive.

                Broker connection
                --
              

              

                
Every operation on this page opens its own
                  short-lived connection and closes it again — deliberately not the gateway's. An ad-hoc
                  consumer on the live channel would eat messages the SmartLocker script is waiting for.
                  Publishing from here and watching the live client receive it is exactly how the scenario at
                  the bottom is meant to be checked.


                
Blank fields fall back to the gateway's configured broker, so the
                  common case needs no typing — and nobody points a topology-creating button at the wrong
                  broker by accident.

Publish

              

                
Sent inside a transaction, so a success means the broker committed
                  it — not merely that the bytes left this process. Note a commit still succeeds for a
                  message no queue was bound to receive: AMQP drops unroutable messages silently.
                  Uses the Exchange and Routing key above.

Consume

              

                
Drains the queue above until it has enough messages or the timeout
                  passes. Peek requeues what it reads, so the message is still there for
                  whoever it was meant for; Ack consumes it for good. An empty result after
                  the timeout is a healthy queue, not a failure.

SmartLocker end-to-end scenario

              

                
Publishes a card event and then watches for it to
                  land: the broker committing a message says nothing about whether this gateway's
                  consumer decoded it, upserted the card and assigned a locker. Each of those is checked
                  separately against the SmartLocker database.


                

                  This publishes to the broker configured on the RabbitMQ tab — by default the
                  live one. The message enters the real card pipeline and any other consumer
                  bound to that exchange will see it. It also creates a real card and takes a real locker in
                  this gateway's database; use the Release button below when you are done.
                


                

                  

                    
                    
                  

                  

                    
                    
                  

                  

                    
                    
                  

                  

                    
                    
                  

                  

                    --
                  

                


                
Routing goes to the exchange and routing key on the
                  RabbitMQ tab, which prefill from this gateway's own topology — the
                  plan's example names (smartlocker.events / employee.card.created)
                  are not what this deployment binds, so a message sent to those would never reach the queue.
